# AGENTS.md — как работать с этим репозиторием

Репозиторий — **витрина публикации сайта ИИЧАВО**: готовые HTML-страницы, которые GitHub Pages
отдаёт наружу. Коммит в `main` = публикация. Инструкция одна для людей и агентов.

## Статус

| Параметр | Значение |
|---|---|
| Этап | тест: публикация по адресу GitHub, домен `ichv.ai` остаётся на Tilda |
| Адрес | `https://ichv-ai.github.io/site/` |
| Источник публикации | ветка `main`, корень репозитория |
| Сборка | нет (`.nojekyll`): файлы отдаются как есть |
| Индексация | закрыта: в каждой странице `<meta name="robots" content="noindex, nofollow">` |

## Репозиторий публичный — что сюда нельзя

Всё содержимое и вся история коммитов видны любому. Удалённое из файла остаётся в истории.

- Только страницы, готовые к показу наружу. Черновики, варианты, бэкапы, заметки — не сюда.
- Никаких секретов, ключей, токенов, внутренних ссылок и личных адресов почты.
- Имя клиента, его цифры и цитаты — только после согласования с клиентом.
- Шрифты и картинки — только с лицензией на веб и распространение. Коммерческий шрифт файлом
  или base64 в страницу не вшивается.
- Сообщения коммитов нейтральные: что изменилось на сайте («Страница prompti: новый блок программы»).
  Без внутренних обсуждений, имён, оценок и причин.
- Автор коммита — с адресом `…@users.noreply.github.com`, не с личной почтой.

## Где страницы делаются и где публикуются

Разработка, черновики, согласования и описание страниц живут во внутреннем рабочем репозитории
агентства. Сюда попадает **только итог** — копия согласованной страницы. Правка текста или вёрстки
делается в источнике, затем копия обновляется здесь. Напрямую здесь правятся только технические
вещи этого репозитория (редиректы, 404, мета-теги публикации).

## Структура и адреса

| Файл | Адрес | Что это |
|---|---|---|
| `index.html` | `/site/` | заглушка-редирект на `https://ichv.ai` (на этапе теста) |
| `prompti.html` | `/site/prompti` | лендинг «Промпти» |
| `404.html` | любой несуществующий адрес | страница «не найдено» |
| `.nojekyll` | — | отключает сборку Jekyll, не удалять |

- Один файл — одна страница. Файл `name.html` открывается и как `/name`, и как `/name.html`;
  в ссылках используем адрес без расширения.
- Имя файла = будущий путь на `ichv.ai`: латиница, нижний регистр, `_` или `-`, без пробелов.
- Страница автономная: стили и скрипты внутри файла. Общие картинки — в `assets/`, ссылки на них
  относительные (`assets/pic.webp`), не от корня (`/assets/…` на тестовом адресе не работает).
- Ссылки между страницами сайта — относительные (`prompti`, не `/prompti`), пока сайт живёт в
  подпапке `/site/`.

## Как добавить или обновить страницу

1. Убедиться, что страница согласована к публикации и проходит раздел «что сюда нельзя».
2. Скопировать итоговый HTML в корень под прод-именем.
3. Проверить в `<head>`: `<title>`, `description`, `og:title`, `og:description`, `lang="ru"`,
   на этапе теста — `noindex, nofollow`.
4. Добавить строку в таблицу «Структура и адреса».
5. Коммит в `main` и push. Через 1–2 минуты (по документации — до 10) страница доступна.
6. Проверить живой адрес: код ответа 200, страница отрисована, в консоли нет ошибок.

Снять страницу — удалить файл и строку в таблице. Файл останется в истории репозитория.

## Чего GitHub Pages не умеет

- Серверного кода нет: формы, запись, оплата — только через внешние сервисы.
- Серверных редиректов нет. Переезд адреса — файл-заглушка со старым именем:
  `<meta http-equiv="refresh" content="0; url=новый-адрес">` + `<link rel="canonical">`.
- Закрытых страниц нет: всё опубликованное открыто.
- Лимиты: сайт до 1 ГБ, 100 ГБ трафика в месяц, 10 сборок в час.

## Аналитика

На этапе теста счётчик Яндекс.Метрики в страницы не ставится: тестовый адрес не должен попадать в
статистику сайта. Вызовы целей в страницах защищены проверкой `typeof ym === 'function'` и без
счётчика молчат.

## Переключение домена `ichv.ai` (не выполнено)

Делается отдельным решением владельца. Шаги:

1. Перенести все боевые страницы, включая настоящую главную вместо заглушки `index.html`.
2. Вставить код счётчика Метрики в каждую страницу.
3. Убрать `noindex, nofollow` со страниц, которые должны индексироваться.
4. Заменить относительные ссылки на ссылки от корня, если это нужно странице.
5. Добавить файл `CNAME` с доменом, в настройках Pages указать домен.
6. У регистратора: четыре A-записи GitHub на корень домена и CNAME `www` → `ichv-ai.github.io`.
7. После выпуска сертификата включить «Enforce HTTPS».
8. Обновить таблицу «Статус» в этом файле.
